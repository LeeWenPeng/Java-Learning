## 1  三个核心注解概览

| 注解 | 参数位置 | 传参方式 | 典型场景 | 示例 URL |
| :--- | :--- | :--- | :--- | :--- |
| **@RequestParam** | URL 查询字符串 | `?key1=value1&key2=value2` | 分页、筛选、搜索 | `/users?page=1&size=10` |
| **@PathVariable** | URL 路径中 | `/resource/{id}` | RESTful 资源定位 | `/users/1001` |
| **@RequestBody** | HTTP 请求体中 | JSON / XML 数据包 | 新增、修改操作 | POST `/users` + JSON 体 |

---

## 2  @RequestParam — 查询参数绑定

**作用**：将 HTTP 请求中的**查询参数（Query String）**绑定到控制器方法的参数上。

**典型格式**：`GET /api/users?page=1&size=10&keyword=spring`

### 2.1  基础用法

```java
@GetMapping("/users")
public String listUsers(
        @RequestParam int page,
        @RequestParam int size,
        @RequestParam String keyword) {
    return "page=" + page + ", size=" + size + ", keyword=" + keyword;
}
```

### 2.2  核心属性

| 属性 | 说明 | 示例 |
| :--- | :--- | :--- |
| **`value` / `name`** | 请求参数名，与前端字段对应 | `@RequestParam("user_name") String name` |
| **`required`** | 是否必须，默认 `true` | `@RequestParam(required = false) String keyword`（不传则 null） |
| **`defaultValue`** | 参数缺失时的默认值（常与 `required=false` 配合） | `@RequestParam(defaultValue = "1") int page` |

### 2.3  支持的数据类型

- 基本类型及包装类（`int`、`Integer`、`boolean` 等）
- 字符串（`String`）
- 数组/集合（`String[]` 或 `List<String>`），用于接收同名多值参数：`?hobby=篮球&hobby=足球`

```java
@GetMapping("/search")
public String search(
        @RequestParam List<String> tags) {  // URL: /search?tags=java&tags=spring
    return "tags=" + tags;
}
```

## 3  @PathVariable — 路径变量绑定

**作用**：从 URL 模板中提取变量值并绑定到方法参数，是构建 **RESTful API** 的核心方式。

**典型格式**：`GET /api/users/1001`

### 3.1  基础用法

```java
@GetMapping("/users/{id}")
public String getUser(@PathVariable Long id) {
    return "User ID: " + id;
}
```

**URL 匹配规则**：`/users/1001` → `id = 1001`

### 3.2  参数名绑定

当路径变量名与方法参数名不一致时，需显式指定：

```java
@GetMapping("/users/{userId}")
public String getUser(@PathVariable("userId") Long id) {
    return "User ID: " + id;
}
```

### 3.3  多个路径变量

```java
@GetMapping("/users/{userId}/orders/{orderId}")
public String getOrder(
        @PathVariable Long userId,
        @PathVariable Long orderId) {
    return "User=" + userId + ", Order=" + orderId;
}
```

### 3.4  路径变量支持正则表达式

```java
@GetMapping("/users/{id:\\d+}")   // 只匹配数字
public String getUserById(@PathVariable Long id) {
    return "User ID: " + id;
}
```

## 4  @RequestBody — 请求体绑定

**作用**：将 HTTP 请求体（Body）中的 JSON/XML 等数据，自动反序列化为 Java 对象。

**典型场景**：POST、PUT 请求提交复杂数据结构。

### 4.1  基础用法

假设前端发送 JSON：

```json
{
    "name": "张三",
    "age": 25,
    "email": "zhangsan@example.com"
}
```

对应的 Java 实体：

```java
public class User {
    private String name;
    private Integer age;
    private String email;
    // getter/setter 省略
}
```

控制器接收：

```java
@PostMapping("/users")
public String createUser(@RequestBody User user) {
    return "创建用户：" + user.getName() + "，年龄：" + user.getAge();
}
```

### 4.2  核心属性

| 属性 | 说明 |
| :--- | :--- |
| **`required`** | 请求体是否必须，默认 `true`。设为 `false` 时若请求体为空则传入 `null`。 |
| **`value`** | 较少使用，通常省略。 |

### 4.3  前端 Content-Type 约定

使用 `@RequestBody` 时，前端请求的 **`Content-Type`** 头必须为：

- `application/json`（最常用）
- `application/xml`
- 或其他 Spring 支持的消息转换器能解析的格式

否则 Spring 无法找到合适的 `HttpMessageConverter`，会返回 `415 Unsupported Media Type`。

### 4.4  与 `@RequestParam` 的混用

```java
@PostMapping("/users/{id}")
public String updateUser(
        @PathVariable Long id,                // 路径变量（RESTful 定位资源）
        @RequestParam String operator,        // 查询参数（操作者标记）
        @RequestBody User user) {             // 请求体（修改内容）
    return "更新用户 " + id + "，操作人=" + operator;
}
```

## 5  使用场景的最佳实践

| 操作类型 | HTTP 方法 | 推荐注解 | 理由 |
| :--- | :--- | :--- | :--- |
| **查询（列表）** | GET | `@RequestParam` | 参数较少，支持分页/过滤，天然可缓存。 |
| **查询（单个）** | GET | `@PathVariable` | RESTful 风格，资源定位清晰。 |
| **新增** | POST | `@RequestBody` | 数据结构复杂，JSON 承载完整业务对象。 |
| **修改（全量）** | PUT | `@RequestBody` | 数据量大，PUT 语义是整体替换。 |
| **修改（部分）** | PATCH | `@RequestBody` | 只传变更字段，JSON 结构灵活。 |
| **删除** | DELETE | `@PathVariable` | 只需资源 ID，无请求体。 |

> **补充**：`@RequestParam` 也可用于 POST 请求的 **表单提交**（`application/x-www-form-urlencoded`），那是传统 HTML 表单的用法；而 `@RequestBody` 接收的是 **JSON/XML 数据包**，是现代前后端分离架构的标准方式。

## 6  进阶补充

### 6.1  `@RestController` 的本质

`@RestController` = `@Controller` + `@ResponseBody`。

- 类上的 `@ResponseBody` 表示所有方法的返回值直接写入 HTTP 响应体，**不经过视图解析器**，适用于纯 JSON 接口（前后端分离）。
- 若用 `@Controller` 不加 `@ResponseBody`，则返回的是视图名称（如 `"index"` → 渲染 `index.html`）。

### 6.2  参数自动转换与类型校验

Spring MVC 内置了丰富的类型转换器：

- `"1"` → `int`/`Integer`
- `"2025-07-20"` → `LocalDate`（配合 `@DateTimeFormat`）
- 若需参数校验，可配合 `@Valid` + Bean Validation（如 `@NotNull`、`@Size`）：

```java
@PostMapping("/users")
public String create(@Valid @RequestBody User user) {
    // 校验失败时会抛出 MethodArgumentNotValidException
}
```

### 6.3  常见状态码（前后端协作理解）

| 场景 | HTTP 状态码 | 说明 |
| :--- | :--- | :--- |
| GET 查询成功 | `200 OK` | 返回数据 |
| POST 创建成功 | `201 Created` | 新资源已创建 |
| PUT/PATCH 更新成功 | `200 OK` 或 `204 No Content` | 后者表示更新成功但无内容返回 |
| DELETE 删除成功 | `204 No Content` | 无返回体 |
| 请求格式错误 | `400 Bad Request` | 参数缺失/类型不匹配/校验失败 |
| 资源不存在 | `404 Not Found` | 路径变量对应资源不存在 |
| 请求体格式错误 | `415 Unsupported Media Type` | Content-Type 不是 application/json |
