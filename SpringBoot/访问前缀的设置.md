## 1 访问前缀的两种设置方式

Spring Boot 提供了**两种粒度的访问前缀**，可以组合使用：

### 1.1 类级别前缀：`@RequestMapping`

在 `@RestController` 或 `@Controller` 类上添加 `@RequestMapping`，为该类中所有接口方法**统一添加公共前缀**。

```java
@RestController
@RequestMapping("/user")  // 所有方法路径都以 /user 开头
public class UserController {
    
    @GetMapping("/list")      // 实际路径：/user/list
    public List<User> list() { ... }
    
    @GetMapping("/{id}")      // 实际路径：/user/{id}
    public User getById(@PathVariable Long id) { ... }
    
    @PostMapping              // 实际路径：/user
    public User create(@RequestBody User user) { ... }
}
```

**作用**：对同一业务模块的接口进行逻辑分组，提升代码可读性。

### 1.2 全局前缀：`server.servlet.context-path`

在 `application.yaml` 中配置，作用于**整个应用的所有接口**。

```yaml
server:
  servlet:
    context-path: /api      # 全局前缀，所有接口都以此开头
```

如果同时配置了上述两种前缀，最终访问路径为：

```java
/api + /user + /list = /api/user/list
```

### 1.3 两种前缀的对比

| 对比维度 | `@RequestMapping` 类级前缀 | `server.servlet.context-path` |
| :--- | :--- | :--- |
| **配置位置** | Java 代码（Controller 类上） | `application.yaml` 配置文件 |
| **作用范围** | 当前 Controller 类中的所有方法 | 整个应用的所有接口 |
| **修改成本** | 需修改代码并重新编译 | 仅修改配置文件，无需重新编译 |
| **适用场景** | 业务模块分组（如 `/user`、`/order`） | 环境区分（如 `/api`、`/api/v1`）或反向代理前缀 |

**最佳实践**：

- 用 `context-path` 管理**大版本**或**环境标识**（如 `/api/v1`）。
- 用 `@RequestMapping` 管理**业务模块**（如 `/user`、`/product`）。
