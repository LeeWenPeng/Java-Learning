## 1  什么是 Restful 风格

Restful 风格是一种软件架构风格，是设计分布式系统的一套设计原则和约束条件。

- 核心思想：将一切功能抽象为对 " 资源 " 的操作，并利用 HTTP 协议本身自带的语义来完成这些操作。

## 2  六大核心约束

- 客户端 - 服务器分离：前端只负责展示，后端只负责数据存储和业务逻辑，两者独立演进
- 无状态：服务器不保存任何客户端的状态信息。每次请求都必须包含所有必要信息。
	- 这意味着服务器宕机时，可以随时切换备用机，因为不需要登录状态的同步
- 可缓存：服务器返回的数据必须标记是否可以缓存
- 统一接口：要求以标准化的方式操作资源，让前后端解耦
- 分层系统：
- 按需代码：服务器可以临时向客户端返回可执行代码来扩展客户端功能。

## 3  RESTful 名词与动词设计

REST 风格把 API 看作是对 " 资源 " 的操作。

- 资源：所有东西都是资源，用 URL 来表示
- 操作：利用 HTTP 协议自带的请求方法作为动词

| HTTP 方法    | 对资源的操作         | 对应 SQL（数据库） |
| ---------- | -------------- | ----------- |
| **GET**    | 获取资源（查询）       | SELECT      |
| **POST**   | 创建新资源（新增）      | INSERT      |
| **PUT**    | 全量更新资源（替换）     | UPDATE（全量）  |
| **PATCH**  | 部分更新资源（修改某个字段） | UPDATE（部分）  |
| **DELETE** | 删除资源           | DELETE      |
