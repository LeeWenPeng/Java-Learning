在 Spring Boot 整合 Redis 时，为 `RedisTemplate` 指定合适的序列化器是至关重要的步骤。默认使用的 JDK 序列化机制会带来可读性差、存储空间大、跨语言不兼容等一系列问题。

因此，在实际项目中，我们通常会自定义配置，为 `RedisTemplate` 设置更优的序列化器。

## 1  有哪些序列化器可以选择？

Spring Data Redis 提供了多种开箱即用的序列化器，你也可以引入第三方库来实现更多选择。

| 序列化器                               | 核心特点                    | 优点                                                         | 缺点                                                               | 适用场景                              |
| :--------------------------------- | :---------------------- | :--------------------------------------------------------- | :--------------------------------------------------------------- | :-------------------------------- |
| JdkSerializationRedisSerializer    | Java 原生序列化              | 开箱即用，支持任意 `Serializable` 对象                                | **可读性差**（Redis 中显示为乱码）<br>**体积大**，占用更多内存<br>**性能较低**，且**跨语言不兼容** | **不推荐用于生产环境**                     |
| StringRedisSerializer              | 直接处理字符串的字节数组            | **性能最优**，简单高效<br>**可读性好**                                  | 只能序列化 `String` 类型                                                | **Key 的序列化首选**<br>Value 为简单字符串的场景 |
| Jackson2JsonRedisSerializer        | 将对象序列化为 JSON            | **可读性好**<br>对象**无需实现 `Serializable`** 接口<br>序列化后的数据**体积小** | 需要**指定具体的对象类型**（如 `User.class`）<br>处理泛型时较麻烦                      | Value 为**已知类型**的复杂对象              |
| GenericJackson2JsonRedisSerializer | Jackson2 的通用版本          | **类型安全**，自动在 JSON 中存储 `@class` 信息<br>无需显式指定类型              | **性能开销**略高于 `Jackson2JsonRedisSerializer`<br>JSON 数据中包含额外类型信息    | Value 为**多种不同类型**的复杂对象            |
| FastJsonRedisSerializer            | 阿里巴巴 Fastjson 实现        | **性能高**，速度快                                                | 需要**引入 Fastjson 依赖**<br>需指定类型                                    | 追求**高性能 JSON 序列化**的场景             |
| KryoSerializer                     | 第三方高性能二进制序列化            | **性能极高**，速度快，体积小                                           | **跨语言支持差**<br>需手动处理类型信息<br>需要引入 Kryo 依赖                          | **对性能要求极高**且类型固定的场景               |
| ProtobufSerializer                 | Google Protocol Buffers | **高性能**，体积小，**跨语言兼容性好**                                    | 需要**定义 `.proto` 文件**，配置复杂<br>需要引入 Protobuf 依赖                    | **跨语言系统**或**对性能要求极高**的场景          |

## 2  如何为 RedisTemplate 配置序列化器？

通常的做法是创建一个配置类，通过 `@Bean` 方法自定义 `RedisTemplate`。

**第一步：引入依赖**

确保你的 `pom.xml` 中包含了 Spring Data Redis 依赖。如果计划使用 Jackson 序列化器，还需引入 `jackson-databind`。

```xml
<dependencies>
    <!-- Spring Data Redis 依赖 -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-data-redis</artifactId>
    </dependency>

    <!-- 连接池依赖（如使用 Lettuce 连接池，Spring Boot 默认使用 Lettuce） -->
    <dependency>
        <groupId>org.apache.commons</groupId>
        <artifactId>commons-pool2</artifactId>
    </dependency>

    <!-- Jackson 序列化支持（用于将对象序列化为 JSON） -->
    <dependency>
        <groupId>com.fasterxml.jackson.core</groupId>
        <artifactId>jackson-databind</artifactId>
    </dependency>
</dependencies>
```

**第二步：编写配置类**

下面是一个**生产环境推荐**的配置模板，将 Key 设置为 `StringRedisSerializer`，Value 设置为 `Jackson2JsonRedisSerializer`。

```java
import com.fasterxml.jackson.annotation.JsonAutoDetect;
import com.fasterxml.jackson.annotation.PropertyAccessor;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.jsontype.impl.LaissezFaireSubTypeValidator;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.redis.connection.RedisConnectionFactory;
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.data.redis.serializer.Jackson2JsonRedisSerializer;
import org.springframework.data.redis.serializer.StringRedisSerializer;

@Configuration
public class RedisConfig {

    @Bean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        // 1. 设置连接工厂
        template.setConnectionFactory(factory);

        // 2. 创建并配置 Jackson2JsonRedisSerializer
        Jackson2JsonRedisSerializer<Object> jackson2JsonRedisSerializer = 
                new Jackson2JsonRedisSerializer<>(Object.class);
        ObjectMapper om = new ObjectMapper();
        // 设置可见性
        om.setVisibility(PropertyAccessor.ALL, JsonAutoDetect.Visibility.ANY);
        // 启用默认类型，以存储类信息，便于反序列化
        om.activateDefaultTyping(LaissezFaireSubTypeValidator.instance, 
                ObjectMapper.DefaultTyping.NON_FINAL);
        jackson2JsonRedisSerializer.setObjectMapper(om);

        // 3. 创建 StringRedisSerializer
        StringRedisSerializer stringRedisSerializer = new StringRedisSerializer();

        // 4. 为 RedisTemplate 设置序列化器
        // key 和 hash key 使用 String 序列化器
        template.setKeySerializer(stringRedisSerializer);
        template.setHashKeySerializer(stringRedisSerializer);
        // value 和 hash value 使用 Jackson 序列化器
        template.setValueSerializer(jackson2JsonRedisSerializer);
        template.setHashValueSerializer(jackson2JsonRedisSerializer);

        template.afterPropertiesSet();
        return template;
    }
}
```

> **注意**：`ObjectMapper` 配置中的 `activateDefaultTyping` 方法是为了在 JSON 中存储类型信息，确保反序列化时能正确还原为原对象类型。如果只存储明确类型的对象（如始终是 `User` 类），可以省略此配置，并在创建序列化器时直接指定类型：`new Jackson2JsonRedisSerializer<>(User.class)`。

## 3  最佳实践总结

- **Key 的序列化**：**始终使用 `StringRedisSerializer`**。这能保证 Key 在 Redis 中清晰可读，方便运维和调试。
- **Value 的序列化**：
	- **首选 JSON 格式**（如 `Jackson2JsonRedisSerializer` 或 `GenericJackson2JsonRedisSerializer`），以获得良好的可读性和跨语言兼容性。
	- 如果存储的对象类型单一，使用 `Jackson2JsonRedisSerializer` 性能更佳。
	- 如果存储的对象类型多变，使用 `GenericJackson2JsonRedisSerializer` 更安全。
- **避免使用默认配置**：永远不要直接使用未配置序列化器的 `RedisTemplate`，这是很多问题的根源。
- **一致性原则**：存入和取出数据时，必须使用**相同的序列化配置**，否则会导致反序列化失败。
