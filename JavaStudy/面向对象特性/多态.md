## 多态是什么？

- 多态提供了另一个维度的接口与实现分离，以解耦做什么和怎么做。
- 多态方法调用允许一种类型表现出与相似类型的区别，只要这些类型派生自一个基类。
- 本质是接口的多种不同实现方式

## 语法

```java
ClassFather nameFather = new ClassChild();
```

- 父类引用指向子类对象
- 父类引用能够访问父类的属性和方法
- 访问时，优先访问子类重写的方法

## 满足多态的条件

- 子类必须继承父类
- 子类必须重写父类的方法
- 父类引用指向子类对象

## 使用多态的好处

- 降低代码之间的耦合度
- 减少冗余代码
- 增加项目扩展能力

## 多态和后期绑定

在多态时，当父类引用指向子类对象，并通过该父类引用调用被子类重写的方法时，编译器将在**运行时**根据**对象类型**进行后期绑定。这也叫做动态多态。

## 多态的类型转换

### 向上转型

父类引用指向子类对象，或者说将子类型赋值给父类型

- 该引用只能访问父类中的属性和方法
- 如果方法为子类独有的，那么会编译错误

#### 案例

场景

- Animal 为父类，有两个子类为 Dog 和 Cat
- Animal 类中有 eat 方法，子类对该方法分别进行了重写
- AnimalKeeperPolymorphic 为饲养员类，有 feed 方法
- 饲养员对 feed 方法进行调用时，传入 Dog 对象或 Cat 对象

代码

```java
package org.example;

public class AnimalKeeperPolymorphic {
    // 形参为父类，实参为子类，则将基类类引用指向子类对象
    // 优先调用子类对象中重写的方法
    public void feed(Animal animal){ 
        animal.eat();
    }
}
```

### 向下转型

基类类型赋值给派生类类型

- 其实就是强制类型转换
- 只有父类引用指向子类对象，并该父类引用向下转换为该子类对象时，向下转换才会成功。否则会会抛出 ClassCastException。
- 建议使用 `instanceof` 关键字进行判断

#### 为什么建议向下转型时进行类型检查

因为当基类对象向下转型为派生类对象时，如果调用了派生类对象独有的方法，而基类对象中没有该方法时，会出现错误。

#### 案例 

场景

- Animal 为基类，有两个派生类为 Dog 和 Cat
- Dog 和 Cat 各有一个独有的方法（基类中没有该方法）

代码  

```java
public static void doAnimalStuff(Animal animal){ 
    if(animal instanceof Dog){
        Dog myDog = (Dog)animal;
        myDog.growl();
    }else if(animal instanceof Cat){
        Cat myCat = (Cat)animal;
        myCat.miowmiow();
    }else{
        animal.makenoise();
    }
}
```

上述代码违背了开口原则，可以将叫这个功能抽取出来，无论是作为一个接口还是直接作为 Animal 的方法。这里是为了展示 instanceof 的用法。

## 多态案例：动物饲养

### 场景

假如有个饲养员，需要给不同的宠物喂食，下面给出使用多态和不使用多态的实现方式。

### 实现

1 动物类 Animal

```java
package org.example;

public abstract class Animal {
    public void eat(){
        System.out.println("动物吃东西！");
    }
}
```

2 狗类 Dog

```java
package org.example;

public class Dog extends Animal{
    @Override
    public void eat(){
        System.out.println("Dog eat");
    }

}
```

3 猫类 Cat

```java
package org.example;

public abstract class Animal {
    @Override
    public void eat(){
        System.out.println("动物吃东西！");
    }
}
```

4 饲养员类（非多态） AnimalKeeper

```java
package org.example;

public class AnimalKeeper {
    public void feed(Cat cat){
        cat.eat();
    }
    public void feed(Dog dog){
        dog.eat();
    }
}
```

5 饲养员类（多态）AnimalKeeperPolymorphic

```java
package org.example;

public class AnimalKeeperPolymorphic {
    // 形参为父类，实参为子类，则将父类引用指向子类对象
    // 优先调用子类对象中重写的方法
    public void feed(Animal animal){ 
        animal.eat();
    }
}
```

6 测试类 PolymorphicTest

```java
package org.example;

public class PolymorphicTest {
    public static void main1(String[] args){
        AnimalKeeper animalKeeper = new AnimalKeeper();

        Cat cat = new Cat();
        animalKeeper.feed(cat);

        Dog dog = new Dog();
        animalKeeper.feed(dog);
    }
    public static void main(String[] args){
        AnimalKeeperPolymorphic animalKeeper = new AnimalKeeperPolymorphic();

        Cat cat = new Cat();
        animalKeeper.feed(cat);

        Dog dog = new Dog();
        animalKeeper.feed(dog);
    }
}
```

### 分析

多态实现代码

```java
public class AnimalKeeperPolymorphic {
    public void feed(Animal animal){ 
        animal.eat();
    }
}
```

属于向上转型，其中feed方法形参为父类，传递给方法的实参为子类对象。其中，

- 继承：子类对象继承了父类，Cat 和 Dog 继承了 Animal
- 重写：子类对象重写父类方法，Cat 和 Dog 重写了 eat 方法
- 父类引用指向子类对象：将子类对象赋值给父类引用
  - 在 AnimalKeeperPolymorphic 对象调用 feed 方法时，将Cat 或Dog对象作为实参传递
  - feed 方法的形参为 Animal 类型
  - 因此，此时为子类对象向上转型为父类对象

## 构造器和多态

构造器的构造顺序

1. 优先构造基类对象。（递归构造父类对象）
2. 按声明顺序初始化成员。（成员对象）
3. 调用派生类构造器的方法体。（本身）

构造器的清理顺序和构造顺序相反

1. 首先清理派生类

1. 按声明顺序的逆序清理成员。
2. 最后清理基类（递归清理）

### 多态清理

问题：在特殊场景下，需要进行手动清理。当派生类重写了基类的清理函数，那么当调用清理函数时，此时会发生多态，派生类的清理函数将覆盖基类的清理函数，从而导致基类的清理函数将不会被调用。因此导致构造的基类对象不会被清理。

解决方法：在派生类重写基类的清理函数时，需要调用基类的清理函数。

#### 案例

场景：基类的清理函数为 dispose

```java
@Override
    protected void dispose() {
        System.out.println("Animal dispose");
        t.dispose(); // 成员的清理
        p.dispose(); // 成员的清理
        super.dispose(); // 调用基类的清理函数
    }
```

### 构造器内部的多态方法

问题：动态多态是在运行时绑定，倘若在构造时调用了动态绑定的方法，而该对象并没有完全构造完成，可能出现BUG

解决思路：做尽量少的事让对象进入良好状态。也就是说，在构造时，尽可能不要调用类内方法，最多只调用类内的 final 方法

#### 案例

```java
// polymorphism/PolyConstructors.java
// Constructors and polymorphism
// don't produce what you might expect
class Glyph {
    void draw() {
        System.out.println("Glyph.draw()");
    }

    Glyph() {
        System.out.println("Glyph() before draw()");
        draw(); // 此时调用了动态方法
        System.out.println("Glyph() after draw()");
    }
}

class RoundGlyph extends Glyph {
    private int radius = 1;

    RoundGlyph(int r) {
        radius = r;
        System.out.println("RoundGlyph.RoundGlyph(), radius = " + radius);
    }

    @Override
    void draw() {
        System.out.println("RoundGlyph.draw(), radius = " + radius);
    }
}

public class PolyConstructors {
    public static void main(String[] args) {
        new RoundGlyph(5); // 构造派生类对象
    }
}
```

##### 分析

1. 上述代码，在 main 函数中构造了派生类 RoundGlyph 对象，那么，其会首先构造基类 Glyph 对象。
2. 在构造 Glyph 对象时，其调用了 draw 方法。由于触发多态，其实会调用派生类中重写的方法。
3. 由于，RoundGlyph 尚未构造完成，因此，此时其分配的存储空间为被编译器初始化的二进制 0。
4. 因此，最终，Glyph调用 draw 打印 `RoundGlyph.draw(), radius = 0`。
5. 而 Glyph  中的 draw 方法将不会被调用。

## 协变返回类型

Java 5 中引入了协变返回类型，这表示派生类的被重写方法可以返回**基类方法返回类型**的**派生类型**。也就是说，当基类方法返回类型为 A，则派生类重写方法返回类型可以为 A 也可以为 A 的派生类型。

### 案例

```java
// 两个返回类型，其中 Grain 为基类，Wheat 为派生类
class Grain {
    @Override
    public String toString() {
        return "Grain";
    }
}

class Wheat extends Grain {
    @Override
    public String toString() {
        return "Wheat";
    }
}

// 多态
// Mill 为基类；WheatMill 为派生类
// Wheat 重写 process 
// 基类 process 返回类型为 Grain
// 子类 process 返回类型可以为 Grain，也可以为 Grain 的派生类 Wheat
class Mill {
    Grain process() {
        return new Grain();
    }
}

class WheatMill extends Mill {
    @Override
    Wheat process() {
        return new Wheat();
    }
}

public class CovariantReturn {
    public static void main(String[] args) {
        Mill m = new Mill();
        Grain g = m.process();
        System.out.println(g);
        m = new WheatMill();
        g = m.process();
        System.out.println(g);
    }
}
```
