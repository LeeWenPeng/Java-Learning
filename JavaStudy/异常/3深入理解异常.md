## 1  异常表 (Exception table)

异常表包含了一个或多个异常处理者的信息

- from：可能发生异常的起始点
- to：可能发生异常的结束点
- target：from 和 to 之前发生异常后的异常处理者的位置
- type：异常处理者处理的异常类的信息

## 2  异常处理流程

当一个异常发生时

1. JVM 会在当前出现异常的方法中查找异常表，寻找是否有合适的处理者进行处理
2. 如果当前方法异常表不为空，而且，查找到匹配的条目（符合 from 和 to 节点，type 也匹配），那么，JVM 将调用位于 target 处的异常处理者对该异常进行处理
3. 在异常表中，从上向下匹配条目，直到找到合适的处理者
4. 如果当前方法的异常表无法处理，则向上查找到调用该方法的调用处（弹栈操作），继续上述操作
5. 如果所有的栈帧被弹出，但仍然没有找到合适的处理者，那么 JVM 就会将该异常抛给当前的 Thread，Tread 就会被终止
6. 如果当前 Thread 为最后一个非守护线程，则未处理异常，则会导致 JVM 终止运行。

## 3  finally 块的一个问题

下述代码返回值是多少？

```java
public int tryInt(){
        int res = 1;
        try{
            res = 2;
            return res;
        }catch(Exception e){
            res = 3;
        }finally {
            res = 4;
        }
        return res;
    }
```

答案：2。

- **返回值在 `finally` 之前确定**：当 `try` 块中有 `return` 语句时，Java 会先计算返回值并保存，然后执行 `finally` 块，最后返回保存的值。即使 `finally` 中修改了返回变量，也不会影响已确定的返回值。
    
- **`finally` 总是执行**：无论是否发生异常，`finally` 都会在 `return` 之前执行（除非 `System.exit` 或 JVM 崩溃）。
    
- **后面的 `return res` 不可达**：因为 `try` 块中已有 `return`，且没有异常，所以方法会在 `finally` 之后直接返回，不会执行到最后的 `return res`。

- 当然，其实后面的 `return res;`，也有可达的可能性。也就是如果 try 中抛出异常，本例中的代码才会执行最后的 return 语句
