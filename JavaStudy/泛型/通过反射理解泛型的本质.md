## 1  一、泛型的两个核心特性再审视


|特性|说明|后果|
|---|---|---|
|**编译时强类型检查**|泛型参数在编译期被验证，确保类型安全。`ArrayList<String>` 的 `add(E)` 方法仅接受 `String` 参数。|阻止了错误的类型赋值，使代码更健壮。|
|**类型擦除**|泛型信息在编译后会被**擦除**，JVM 字节码中并不保留泛型实参。`ArrayList<String>` 在运行时就是 `ArrayList`。|运行时泛型约束完全消失，反射可以突破编译期禁令。|

> 结论：**Java 泛型是纯粹的编译期语法糖，其安全保障仅限于 `javac` 阶段。**

## 2  通过反射绕过泛型

```java
package org.Reflection;

import java.lang.reflect.InvocationTargetException;
import java.lang.reflect.Method;
import java.util.ArrayList;

public class Test2 {
    public static void main(String[] args) throws NoSuchMethodException, InvocationTargetException, IllegalAccessException {
    
        ArrayList<String> a2 = new ArrayList<>();

        a2.add("hello");
        // a2.add(2); 因为强类型检查，参数非 String 类型，会报错

        Class<?> c2 = a2.getClass();

        Method m = c2.getDeclaredMethod("add", Object.class);

        m.invoke(a2, 2); 

        System.out.println(a2.size()); // 2 成功添加 int 类型数据
        
        //        for(String s : a2){ 
		//            System.out.println(s);
		//        }
		// 用 `for(String s : a2)` 遍历
		// JVM 会在取出 `Integer` 元素时尝试将其强制转换为 `String`
		// 从而抛出 `ClassCastException`。
    }
}
```

泛型信息被擦除后，JVM 字节码中的方法签名变为：

```java
public boolean add(Object e);
```

反射调用时，虚拟机只检查方法签名和参数类型的兼容性，`int` 自动装箱为 `Integer` 后可以赋值给 `Object`，因此调用成功。

**核心结论**：

> **泛型提供的类型安全仅限于编译期可见的代码路径。一旦使用反射、字节码增强或原始类型（Raw Type）等绕过编译器检查的手段，泛型约束将形同虚设。**
