## 1  Java 泛型学习笔记

### 1.1  前言：为什么需要泛型

#### 1.1.1  问题背景

在 Java 中，若想为多种数据类型提供相同的算法或数据结构（例如容器类），一个简单粗暴的方案是使用 `Object` 作为参数类型。借助里氏替换原则，`Object` 类型的参数可以接收任意对象。

```java
// 基于 Object 的容器
public class Box {
    private Object item;
    public void set(Object item) { this.item = item; }
    public Object get() { return item; }
}
```

#### 1.1.2  Object 方案的缺陷

- **类型不安全**：编译器只知道操作的是 `Object`，无法在编译期发现类型错误。
- **强制类型转换**：取出数据时必须手动向下转型，稍有不慎就会引发 `ClassCastException`。
- **代码冗余且容易出错**。

```java
Box box = new Box();
box.set("hello");
Integer value = (Integer) box.get(); // 运行时抛出 ClassCastException
```

#### 1.1.3  泛型的引入

Java 借鉴 C++ 模板思想引入了**泛型（Generics）**，允许在定义类、接口、方法时使用**类型参数**，将类型安全检查提前到编译期，同时消除强制类型转换。

#### 1.1.4  泛型的优势

- **编译时强类型检查**：类型错误在编译阶段即被捕获。
- **消除显式类型转换**：代码更简洁、安全。
- **实现真正的通用算法与数据结构**：一套代码适配多种类型。

### 1.2  泛型类型

#### 1.2.1  泛型类

##### 2.1.1 语法

```java
// 单类型参数
public class 类名<T> { }

// 多类型参数
public class 类名<T1, T2> { }
```

- `T` 为**类型占位符**（形式类型参数），需通过 `<T>` 声明才能在类内部使用。
- 编译时，编译器会用实际传入的类型替换 `T` 并进行类型检查。

##### 2.1.2 示例

```java
public class Box<T> {
    private T item;
    public void set(T item) { this.item = item; }
    public T get() { return item; }
}
```

#### 1.2.2  实例化泛型类

```java
Box<String> stringBox = new Box<>();
```

- 实际类型参数 `T` **不能为基本类型**（如 `int`、`double`），必须使用对应的包装类（`Integer`、`Double` 等）。
- Java 7 起支持**菱形语法**（`<>`），可自动推断类型。

#### 1.2.3  类型安全示例

使用泛型后，错误在编译期即可暴露：

```java
Box<String> stringBox = new Box<>();
stringBox.set("hello");
// stringBox.set(123);        // 编译错误：不兼容的类型
String s = stringBox.get();   // 无需强制转换
```

#### 1.2.4  泛型接口

接口亦可声明类型参数：

```java
public interface Generator<T> {
    T next();
}
```

实现泛型接口时有两种选择：

1. **保持泛型**：实现类依然为泛型类。
2. **指定具体类型**：实现类明确类型参数。

```java
// 保持泛型
public class GenericGenerator<T> implements Generator<T> {
    @Override
    public T next() { return null; }
}

// 明确类型
public class IntegerGenerator implements Generator<Integer> {
    @Override
    public Integer next() { return 42; }
}
```

### 1.3  泛型方法

即便类不是泛型类，其方法也可以独立声明类型参数。

```java
public class Util {
    public static <T> void print(T item) {
        System.out.println(item);
    }
}
```

- 类型参数声明放在返回值类型之前：`<T>`。
- 方法内部可将 `T` 作为类型使用。

#### 1.3.1  类型参数推断

调用泛型方法时，编译器通常能**自动推断**类型参数，无需显式指定。

```java
Util.print("hello");          // 推断为 String
Util.print(123);              // 推断为 Integer
```

**注意**：当泛型方法的返回值作为另一个泛型方法的参数时，类型推断可能受限（尤其在链式调用中），有时会被视为 `Object`，需根据实际场景使用显式类型参数或临时变量协助推断。

### 1.4  类型边界（Bounded Type Parameters）

通过 `extends` 关键字可限制类型参数必须为某个类的子类或某些接口的实现，从而在泛型代码中安全调用该边界类型的方法。

#### 1.4.1  泛型类的类型边界

```java
public class Printer<T extends Animal> {
    private T target;
    public Printer(T target) { this.target = target; }
    public void printName() {
        // 由于 T 是 Animal 的子类型，可安全访问 name 属性/方法
        System.out.println(target.getName());
    }
}
```

多重边界语法：

```java
<T extends ClassA & InterfaceB & InterfaceC>
```

- 若边界包含类，则类必须出现在最前，其余为接口。
- 最多一个类边界，多个接口边界用 `&` 连接。

#### 1.4.2  泛型方法的类型边界

```java
public static <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) > 0 ? a : b;
}
```

### 1.5  类型擦除（Type Erasure）

#### 1.5.1  实现机制

Java 泛型通过**类型擦除**实现：

- 编译后，所有类型参数被替换为**其最左边界**（未指定边界则为 `Object`）。
- 必要时插入**桥接方法**以维持多态。
- 移除所有类型参数声明（`<>` 及内部内容）。

示例：

```java
public class Box<T> {           // 源码
    private T item;
}
// 编译后等价于
public class Box {
    private Object item;
}
```

若指定边界 `T extends Animal`，则擦除后 `T` 被替换为 `Animal`。

#### 1.5.2  重要推论

- **运行时不存在泛型类型信息**。
- `List<Integer>` 与 `List<String>` 的 `Class` 对象相同，均为 `List.class`。
- **泛型类型不存在继承关系**：`List<Integer>` 不是 `List<Number>` 的子类型，即使 `Integer` 是 `Number` 的子类。

```java
List<Integer> ints = new ArrayList<>();
List<Number> nums = ints;   // 编译错误：类型不兼容
```

### 1.6  通配符（Wildcards）

为了增加泛型代码的灵活性，Java 提供通配符 `?` 表示未知类型。

| 通配符形式 | 含义 | 典型应用场景 |
|------------|------|--------------|
| `?` | 任意类型 | 不关心具体类型，仅调用与类型无关的方法 |
| `? extends T` | 上界通配符，T 或 T 的子类型 | 从结构中**读取**数据（生产者） |
| `? super T` | 下界通配符，T 或 T 的父类型 | 向结构中**写入**数据（消费者） |

#### 1.6.1  通配符解决泛型类型不可协变问题

```java
List<? extends Integer> ints = new ArrayList<>();
List<? extends Number> nums = ints;   // 编译通过
```

#### 1.6.2  PECS 原则（Producer Extends, Consumer Super）

- 需要从集合中**获取**元素（生产者）：使用 `? extends T`。
- 需要向集合中**放入**元素（消费者）：使用 `? super T`。
- 既要获取又要放入：**避免使用通配符**，使用具体类型参数。

---

### 1.7  泛型使用约束

| 限制项                    | 说明                                       |
| ---------------------- | ---------------------------------------- |
| 类型参数不能为基础类型            | 必须使用包装类（如 `Integer`）或其他类                 |
| 不能实例化类型参数              | `new T()` 非法（类型擦除后无具体类型信息）               |
| 不能声明类型参数的静态字段          | `static T field;` 非法（静态成员属于类，与类型参数无关）    |
| 不能对类型参数使用 `instanceof` | 运行时类型信息已擦除                               |
| 不能创建参数化类型的数组           | `new T[10]` 或 `new List<String>[10]` 均非法 |
| 不能抛出或捕获泛型类异常           | `catch (T e)` 不合法                        |
| 仅泛型参数不同的方法不能重载         | 擦除后方法签名相同，冲突                             |

### 1.8  最佳实践与命名惯例

#### 1.8.1  常用类型参数命名

| 字母 | 含义 |
|------|------|
| E | Element（集合元素） |
| K | Key（键） |
| V | Value（值） |
| N | Number（数值） |
| T | Type（一般类型） |
| S, U, V | 第二、第三、第四类型参数 |

#### 1.8.2  使用建议

- **消除未经检查的警告**：能通过设计避免的警告应予以消除，无法消除时使用 `@SuppressWarnings("unchecked")` 并添加注释说明。
- **优先使用泛型集合而非数组**：泛型集合提供编译时类型安全。
- **善用泛型方法**：即使类不是泛型的，方法也可以是泛型的，以限制作用范围。
- **合理使用有界通配符**：提升 API 的灵活性，遵循 PECS 原则。
- **考虑类型安全的异构容器**：如将 `Class<T>` 作为键，实现可存储多种类型的安全容器。
