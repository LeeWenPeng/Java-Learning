## 1  IO 操作的两个核心阶段

I/O 操作的过程可以分解为两个关键阶段，基于这两个阶段的不同处理方式，构成了不同的 I/O 模型。

### 1.1  数据就绪阶段

- **定义：** 指应用程序询问内核，某个 I/O 操作（如读取网络数据）是否已经准备就绪，可以立即执行而不会发生等待。

#### 1.1.1  阻塞和非阻塞

- **阻塞：** 发起 I/O 请求的线程会被挂起（休眠），直到内核确认数据就绪后才会被唤醒并继续执行。**在等待期间，线程不占用 CPU。**
- **非阻塞：** 发起 I/O 请求后，**线程立即得到一个返回状态**（成功或 " 未就绪 "），而不会被挂起。线程可以继续执行其他任务，但通常需要不断地轮询内核以检查状态。

### 1.2  数据拷贝阶段

- **定义：** 指数据在**应用程序内存**和**内核缓冲区**之间进行实际传输的过程。

#### 1.2.1  同步和异步

- **同步：** 数据的读写操作是由**请求方（应用程序）自身**调用并完成的。应用程序需要主动地、等待地将数据从内核缓冲区读入用户空间，或者将数据从用户空间写入内核缓冲区。
- **异步：** 数据的读写操作是由**被请求方（内核/操作系统）** 独立完成的。应用程序只需发起一个 I/O 请求并提供一个目标缓冲区，内核会完成所有工作，并在整个操作（包括数据拷贝）完成后通知应用程序。

### 1.3  总结

> [!Tip]
> - 处理 IO 时，阻塞和非阻塞都是同步 IO，只有使用了特殊的 API 才是异步 IO

**" 处理 IO 时，阻塞和非阻塞都是同步 IO"**

- 阻塞和非阻塞描述的仅仅是**数据就绪阶段**的等待方式，而同步描述的是**数据读写阶段**的行为。无论是阻塞地等待数据就绪，还是非阻塞地轮询数据就绪，最终到数据拷贝这一步，都需要应用程序线程主动调用 `read`/`write` 等**同步**方法来完成。因此，它们都属于同步 I/O 的范畴。

**" 只有使用了特殊的 API 才是异步 IO"**

- 异步 I/O 需要操作系统提供专门的支持和一套不同的 API（如上面提到的 `aio_*` 或 `IOCP`）。它不仅仅是等待方式的不同，而是整个工作流程的根本性改变。

## 2  五种 IO 模型

### 2.1  阻塞 I/O (Blocking I/O)

![1-BIO](img/Unix_Linux底层的五种IO模型/1-BIO.md)

- **工作流程**：
    1. 应用程序调用一个 I/O 函数（如 `recv`, `accept`）。
    2. 该函数会一直**阻塞**（等待），直到系统内核将数据准备好或收到连接。
    3. 在此期间，应用程序进程被挂起，不能执行任何其他操作，只能等待。
    4. 直到数据从内核空间拷贝到用户空间，函数才返回，进程才继续执行。
- **特点**：**最简单**、最常用的一种模型。在等待期间，进程消耗 CPU 资源为 0，但并发处理能力差。

### 2.2  非阻塞 I/O (Non-blocking I/O)

![2-NIO](img/Unix_Linux底层的五种IO模型/2-NIO.md)

- **工作流程**：
    1. 将套接字设置为非阻塞模式后，应用程序调用 I/O 函数。
    2. 该函数会**立即返回**，而不会使进程阻塞。
    3. 如果事件（如数据就绪）**没有发生**，函数返回一个特定的错误码（如 `EAGAIN` 或 `EWOULDBLOCK`），告知应用程序 " 请重试 "。
    4. 应用程序需要不断地**轮询（polling）** 内核，检查操作是否就绪。在轮询间隔期间，它可以去做其他任务。
- **特点**：通过轮询避免了进程阻塞，但轮询过程会消耗大量的 CPU 时间，效率通常很低。

### 2.3  I/O 多路复用 (I/O Multiplexing)

![3-IO多路复用](img/Unix_Linux底层的五种IO模型/3-IO多路复用.md)

- **工作流程**：
    1. 应用程序首先将多个需要监视的文件描述符（如多个 socket）告诉内核（通过 `select`, `poll`, `epoll` 等函数）。
    2. 然后调用这些函数，这个调用过程本身是**阻塞**的。
    3. 与阻塞 I/O 不同，它可以**同时阻塞多个 I/O 操作**。内核会 " 监视 " 所有被注册的描述符。
    4. 当其中任何一个或多个描述符对应的 I/O 事件（如可读、可写）就绪时，函数返回。
    5. 应用程序再对就绪的描述符进行真正的 I/O 操作（如 `recv`），此时因为数据已就绪，这个操作会很快完成。
- **特点**：**也称为事件驱动 I/O**。==它用单个进程/线程就可以管理多个 I/O 连接==，是构建高性能网络服务器的核心模型。`select`/`poll`/`epoll` 是此模型的关键实现，其性能依次优化。
- 在这个工作中，使用 `select`, `poll`, `epoll` 等函数是使用了两个系统调用，而不像 BIO 和 NIO 都只进行了一次系统调用

I/O 多路复用并非异步 I/O

I/O 多路复用（如 `epoll`）常被误称为 " 异步 "，但它本质上是**用一个线程阻塞地管理多个 I/O 通道的就绪状态**，一旦某个通道就绪，实际的 `read`/`write` 操作仍然是同步的。因此它属于同步非阻塞模型的高效实现，而非异步模型。

### 2.4  信号驱动 I/O (Signal-driven I/O)

![4-信号驱动IO](img/Unix_Linux底层的五种IO模型/4-信号驱动IO.md)

- **工作流程**：
    
    1. 应用程序首先安装一个信号处理函数（用于处理 `SIGIO` 信号）。
    2. 然后为套接字开启信号驱动模式，进程**立即返回**并可以继续执行其他代码。
    3. 当内核数据准备就绪时，它会向应用进程发送一个 `SIGIO` 信号。
    4. 应用程序在之前注册的信号处理函数中调用 I/O 操作（如 `recv`）来读取数据。
- **特点**：进程在数据等待阶段不被阻塞，可以执行其他任务。当数据就绪时，通过信号进行异步通知。**注意**：通知的是 " 数据已就绪 "，实际的 I/O 操作（数据拷贝）仍需要进程在信号处理函数中**同步**完成。

### 2.5  异步 I/O (Asynchronous I/O)

![5-异步IO](img/Unix_Linux底层的五种IO模型/5-异步IO.md)

- **工作流程**：
    
    1. 应用程序发起一个异步 I/O 操作（如 `aio_read`）。
    2. 该函数**立即返回**，进程继续执行，完全不阻塞。
    3. 应用程序告诉内核：缓冲区指针、大小、文件偏移等信息。
    4. 内核会**独自完成所有工作**：等待数据就绪、以及将数据从内核空间**拷贝到用户空间**。
    5. 在整个 I/O 操作（等待 + 拷贝）**彻底完成后**，内核再通过信号或回调函数等方式通知应用程序。
- **特点**：**真正的异步**。应用程序从调用到收到通知的整个过程中，都没有任何阻塞。它与**信号驱动 I/O 的关键区别**在于：信号驱动 I/O 由内核通知我们**何时可以开始**一个 I/O 操作（数据就绪），而异步 I/O 由内核通知我们**I/O 操作何时已经完成**（数据已拷贝完成）。

## 3  核心区别总结

|模型|第一阶段 (等待数据)|第二阶段 (拷贝数据)|核心思想|常用 API（举例）|
|:--|:--|:--|:--|---|
|**阻塞 I/O**|阻塞|阻塞|最简单，全程等待|`read`, `recv`|
|**非阻塞 I/O**|非阻塞（需轮询）|阻塞|轮询检查状态，避免等待时阻塞|`read` (设 `O_NONBLOCK`)|
|**I/O 多路复用**|阻塞（在 select/epoll 上）|阻塞|一个进程监控多个连接|`select`, `poll`, `epoll`|
|**信号驱动 I/O**|非阻塞（由信号通知）|阻塞|用信号通知 I/O 就绪事件|`fcntl` (设 `O_ASYNC`)|
|**异步 I/O**|非阻塞|非阻塞（由内核完成并通知）|真正的异步，内核完成所有工作后通知|`aio_read`, `IOCP`|

**同步 vs. 异步**：

根据 POSIX 的定义，判断一个模型是同步还是异步，关键在于**真正的 I/O 操作（数据拷贝）是否会阻塞进程**。

- **阻塞 I/O、非阻塞 I/O、I/O 多路复用、信号驱动 I/O** 都属于**同步 I/O**，因为它们在 `recvfrom` 调用将数据从内核拷贝到用户空间时，进程都是被阻塞的。
- 只有**异步 I/O 模型**是真正的**异步 I/O**，因为整个过程，进程都没有被阻塞。
