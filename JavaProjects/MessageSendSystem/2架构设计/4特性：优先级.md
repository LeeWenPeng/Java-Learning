## 1  为什么需要支持优先级？

1. 关键消息的优先处理
2. 避免低优消息堵住通道
3. 提升重要客户的体验感

## 2  如何实现优先级？

### 2.1  方案一：分桶

为不同的消息类型分配优先级，并使用多个队列存放不同优先级的消息。

比如，使用优先级不同的高中低三个消息队列

- `msg_queue_low`：存放普通消息
- `msg_queue_middle`：存放比较重要的消息
- `msg_queue_high`：存放十分要紧的消息

其中，高优先级的消息一定是比较少的。否则，优先级的设计就没有意义了。

在消息队列中，可以通过建立多个 `Topic` 来实现方案一。

#### 2.1.1  调度策略

- 方法一：资源独占。低优先级队列和高优先级队列都有对应的调度资源。
- 方法二：按时间划分。在一定时间内，按照比例调度各级队列。比如，高优先级 70%，中优先级 20%，低优先级 10%。

### 2.2  方案二：有序队列

通过有序数据结构存储消息，存储时按照优先级排序。

如果使用 MySQL 作为存储组件，由于 MySQL 索引的底层为 B+ 树，为有序结构，可以实现该方案。

### 2.3  方案的选择

- 当优先级较少时，可以使用 Kafka 做消息中转站，实现方法是在 Kafka 中建立多个 Topic 对应优先级。
- 当优先级较多时，由于 Kafka 支持的消息主题为百级，当优先级数量超过 100 时，性能会很低下。这时，可以使用 MySQL 做消息中转站，使用 `ORDER BY priority` 来实现方案二。

## 3  何时设置消息的优先级？

一般有两种思路：

1. 静态分配，在系统设计时，根据业务类型和需求为消息分配优先级
	1. 比如，紧急警告消息为高优先级，营销推送消息为低优先级等
2. 动态分配，根据运行时上下文或用户行为为消息动态调整优先级
	1. 当用户在线时，提高实时消息的优先级
	2. 当消息重试次数增加时，提升其优先级
	3. 当消息等待时间变长时，逐渐提升其优先级

对于本系统，

- 消息队列作为消息中转站时，采用高优队列模式，是在用户传入参数时就确定了优先级。（静态分配）
- MySQL 作为消息中转站时，则采用动静结合的模式
	- `ORDER BY priority, modify_time`
	- 用户在消息传递时就支持传递优先级，优先调度优先级高的消息
	- 在优先级相同时，就按照访问时间来调度，优先调度更久未被访问的消息

## 4  实际场景

|      | 电商平台             | 金融系统           | 社交应用         |
| ---- | ---------------- | -------------- | ------------ |
| 高优先级 | 支付成功通知<br>下单成功通知 | 交易异常通知<br>到账通知 | 好友请求<br>实时消息 |
| 中优先级 | 物流状态更新           | 账户变动通知         | 点赞评论提醒       |
| 低优先级 | 促销活动推送           | 市场行情更新         | 群组活动推荐       |
