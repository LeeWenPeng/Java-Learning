## 1  前言

推送系统需要进行额度限制，一是第三方平台往往会有流量限制，二是额度限制也能保护下游应用不会因为突然的流量而挂掉。

一般是通过**默认限制**来实现，比如，1 分钟 100 次。同时，面对 VIP 客户，可以单独配置更大额度。

## 2  配置额度信息

可以在 MySQL 配置额度信息，包括全局额度、特定业务额度等。

### 2.1  全局配额表 `t_global_quota`

用于业务渠道的默认配额设置（面向普通用户）

| 字段            | 类型           | 说明                                              |
| ------------- | ------------ | ----------------------------------------------- |
| `id`          | `bigint(20)` | 主键自增 ID                                         |
| `channel`     | `int(10)`    | 消息类型。1: 邮件；2: 短信；3: 飞书                          |
| `num`         | `int(10)`    | 限频数，单位：s                                        |
| `unit`        | `int(10)`    | 限频单位，单位：ms。支持 2 个选项：<br>1000——1s<br>60000——1min |
| `create_time` | `datetime`   | 创建时间                                            |
| `modify_time` | `datetime`   | 修改时间                                            |

### 2.2  渠道配额表 `t_source_quota`

记录某个业务可发送消息的频率。如果业务渠道同时配置了全局配额表和业务配额表，那么以业务配额表为准。

| 字段            | 类型             | 说明                                              |
| ------------- | -------------- | ----------------------------------------------- |
| `id`          | `bigint(20)`   | 主键自增 ID                                         |
| `source_id`   | `varchar(256)` | 业务 ID                                           |
| `channel`     | `int(10)`      | 消息类型。1: 邮件；2: 短信；3: 飞书                          |
| `num`         | `int(10)`      | 限频数，单位：s                                        |
| `unit`        | `int(10)`      | 限频单位，单位：ms。支持 2 个选项：<br>1000——1s<br>60000——1min |
| `create_time` | `datetime`     | 创建时间                                            |
| `modify_time` | `datetime`     | 修改时间                                            |

## 3  限额器 (Redis 实现)

### 3.1  实现步骤

1. 定义 Redis 计数器，键名格式：`rate_limit:{业务ID}:{channel}:{时间戳}`
	1. 示例：`rate_limit:{source123:2:202412071015}`
2. 请求时：
	1. 使用 Redis 的 `INCR` 操作递增计数器
	2. 检查计数器是否为 `1`
		1. 如果为真，说明该计数器是新创建的，则设置过期时间（根据传入参数）。
	3. 检查计数器是否超过限额
		1. 如果超过限额，则返回错误
		2. 否则，允许请求

### 3.2  优缺点

优点

- 实现简单，操作方便
- 性能高，至少能支持几万每秒的请求量

缺点

- 需要引入 Redis，增加运维成本
	- 由于本系统使用 Redis 做缓存，因此，该缺点不存在

## 4  Java 示例

```Java
package Object.AliyunTest;

import redis.clients.jedis.Jedis;

/**
 * @BelongsProject: 消息推送系统
 * @BelongsPackage: Object.AliyunTest
 * @Author: Lee
 * @CreateTime: 2026-07-07 10:39
 * @Description: 额度限量器
 * @Version: 1.0
 */
public class RedisRateLimiter {
    private final Jedis jedis;
    private final int limit;

    public RedisRateLimiter(Jedis jedis, int limit) {
        this.jedis = jedis;
        this.limit = limit;
    }

    public boolean isRequestAllowed(String sourceID, int channel, String div) {
        return isRequestAllowed(sourceID, channel, div, String.valueOf(this.limit));
    }

    /**
     *
     * @param sourceID：业务ID
     * @param channel：消息类型。1:邮件；2: 短信；3: 飞书
     * @param div：限频单位，单位：ms。支持 2 个选项： 1000——1s；60000——1min
     * @param limit
     * @return 消息的计数是否超出阈值
     */
    public boolean isRequestAllowed(String sourceID, int channel, String div, String limit) {
        // 获取 key
        long divL = Integer.parseInt(div);
        long currentStart = System.currentTimeMillis() / divL; // 当前时间段的起始时间戳
        String key = "rate_limit:" + sourceID + ":" + channel + ":" + currentStart; // 限制器键名

        // value 递增
        long count = jedis.incr(key); // 递增计数器

        // 判断计数是否为 1
        if(count == 1){
            // 如果计数为 1，说明该键为新增键，设置过期时间
            jedis.expire(key,divL / 1000);
        }

        // 判断是否超出限制
        return count <= Integer.parseInt(limit);
    }

    public static void main(String[] args) {
        try(Jedis jedis = new Jedis("localhost")) { // 连接本地 Redis
            RedisRateLimiter rateLimiter = new RedisRateLimiter(jedis, 10);

            for(int i = 0; i < 15; ++i){
                System.out.println(rateLimiter.isRequestAllowed("source123", 2, "60000"));
            }
        }
    }
}s
```
