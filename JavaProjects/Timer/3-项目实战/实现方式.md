## 如何提供微服务接口

微服务之间的调用，xTimer 采用的是 OpenFeign

### 什么是 `OpenFeign`

OpenFeign 是 Spring Cloud 生态中的一个**声明式 HTTP 客户端**。它让你能用调用本地方法的方式，去调用远程的 HTTP 服务，极大地简化了微服务之间的通信。

在 OpenFeign 出现前，主要使用 RestTemplate 手动拼接 URL、处理参数和响应，代码繁琐且容易出错。

> **核心原理**：OpenFeign 在启动时会扫描 `@FeignClient` 接口，利用 **JDK 动态代理**技术为它们生成代理对象。当你调用接口方法时，实际上是调用了代理对象，代理对象会根据方法上的注解信息（如 `@GetMapping`），动态构造 HTTP 请求并发送给远程服务。

接口定义标准步骤：

1. **定义接口并加注解**：定义一个接口，并加上 `@FeignClient(name = "目标服务名")` 注解。_(注：这里的 name 通常对应注册中心（`application.xml`）里的服务名，而非具体的 IP)_。
2. **声明方法与路径**：在接口方法上，使用和 Spring MVC 一样的注解（如 `@GetMapping`），来声明要调用的远程 HTTP 接口的路径和参数。

#### 引入 OpenFeign

引入 Spring Cloud 和 OpenFeign

```xml
<!-- spring cloud -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-dependencies</artifactId>
    <version>${spring-cloud.version}</version>
    <type>pom</type>
    <scope>import</scope>
</dependency>

<!-- OpenFeign  -->
<dependency>
	<groupId>org.springframework.cloud</groupId>
	<artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>
```

### 架构设计规范：使用公共 API 模块

在 xTimer 项目中，所有微服务对外提供的接口定义，都统一存放在公共 API 模块（`bitstorm-svr-api`）中。

- **设计目的**：**解耦与复用**。调用者只需要依赖这一个公共 module，就可以调用所有微服务的接口。如果每个微服务都单独定义一个 API module，调用者就会面临依赖泛滥的问题。
- **职责划分**：
	- `bitstorm-svr-api`：只存放接口定义（Feign Client）。
	- 服务提供者：负责编写具体的业务逻辑并提供 HTTP 接口。
	- 服务消费者：依赖公共 API 模块，发起调用。

### 实战使用方式
#### 接口定义

> 接口定义在公共 API module ( `bitstorm-svr-api`) 中

在 `bitstorm-svr-api` 中新建接口 (`DemoClient`)，并添加 `@FeignClient` 注解。

```java
package cn.bitoffer.api.feign;

import org.springframework.cloud.openfeign.FeignClient;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;

// name 属性指定了目标微服务的名称（需与注册中心中的服务名一致）
@FeignClient("cron-system")
public interface DemoClient {

    /**
     * demo 服务接口
     */
    @GetMapping(value = "/call")
    public String call(@RequestParam("name") String name);
}
```

#### 接口实现

> 接口实现在服务提供者模块中

接口实现存放在服务提供者各自的 module 中。因为服务实现逻辑，只有服务提供者关心，所以存放在各自的 module 中。

具体来说，存放在各自 module 的 `feign` 包下 (例如，`feign` 包下的实现类 `DemoFeignController`)

#### 接口调用

> 可以参考 `bitstorm-svr-testconsumer` module 下的 `cn.bitoffer.testconsumer.controller.ConsumerController`

调用者（如 `bitstorm-svr-testconsumer`）需要完成以下三步：

第一步：引入 API 模块依赖

在 `pom.xml` 中引入接口所在的包：

调用者 (`bitstorm-svr-testconsumer`) 需要引入 pom 依赖 。也就是，引入接口所在的包 (`bitstorm-svr-api`)；

```xml
		<dependency>
            <groupId>bitoffer.cn</groupId>
            <artifactId>bitstorm-svr-api</artifactId>
            <version>${project.version}</version>
        </dependency>
        
        <dependency>
            <groupId>org.springframework.cloud</groupId>
            <artifactId>spring-cloud-starter-openfeign</artifactId>
        </dependency>
```

- 然后，像调用本地方法一样，调用接口 (`DemoClient`) 提供的方法 (`call`)
	- 将接口注入类
	- 接口对象调用接口方法

### Mapper 相关

#### 定义接口

> 定义对数据库的操作方法，比如增删改查等，见 `com.demo.xTimerSystem.mapper.ExampleMapper`

#### 实现接口

> 通过 mybatis 方式，在 xml，实现每种接口的逻辑。见 `src/main/resources/mapper/ExampleMapper.xml`

#### `ExampleMapper.xml` 详解

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!-- DOCTYPE 声明 -->
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<!-- namespace 必须是 mapper 接口的全限定名  -->
<mapper namespace="com.demo.xTimerSystem.mapper.ExampleMapper">
<!--    结果映射规则，将数据库中的 column 映射到 java 中的 property -->
<!--    type：结果集要映射到实体类的权限定名 -->
    <resultMap id="exampleMap" type="com.demo.xTimerSystem.model.Example">
<!--        主键列映射 -->
        <id column="example_id" property="exampleId"/>
<!--        result 普通列映射 -->
        <result column="create_time" property="createTime"/>
        <result column="update_time" property="updateTime"/>
        <result column="example_name" property="exampleName"/>
        <result column="status" property="status"/>
    </resultMap>

<!--    <sql> 用于抽取可复用的 SQL 片段，通过 <include refid="Vo_Column_List"/> 引用 -->
<!--    由于下述的 select 并没有使用，因此此段也是未使用的配置 -->
    <sql id="Vo_Column_List">
        `example_id`,
        `create_time`,
        `update_time`,
        `example_name`,
        `status`
    </sql>
<!--    插入方法 -->
<!--    id 就是 Mapper 中的方法名-->
<!--    useGeneratedKeys="true" 告诉 MyBatis 使用 JDBC 的`getGeneratedKeys()` 获取数据库的自增主键 -->
<!--    keyProperty="example.exampleId" 把获取到的主键回填到 example.exampleId -->
<!--    #{example.exampleName},#{example.status} 从 exmaple 对象中读取 exampleName 和 status -->
    <insert id="save" useGeneratedKeys="true" keyProperty="example.exampleId">
        insert into example (`example_name`,`status`)
        values (#{example.exampleName},#{example.status});
    </insert>
<!--    删除方法 -->
<!--    #{} 包裹的变量，为Mapper 方法中 @Param 注解传递的变量 -->
    <delete id="deleteById">
        delete from example where example_id = #{exampleId};
    </delete>
<!--    更新方法 -->
<!--    <set> 会自动做两件事：
    1. 在内容前插入 SET 关键字；
    2. 去掉动态拼接后末尾多余的逗号。
    因此，每个每个 <if> 里末尾写逗号是正确且常见的写法，最终的 SQL 不会多个逗号
    -->
    <update id="update">
        update example
        <set>
<!--            <if test="example.exampleId != null">-->
<!--                `example_id` = #{example.exampleId},-->
<!--            </if>-->
            <if test="example.exampleName != null">
                `example_name` = #{example.exampleName},
            </if>
            <if test="example.status != null">
                `status` = #{example.status},
            </if>
        </set>
        where example_id = #{example.exampleId};
    </update>
<!--    查询方法 -->
<!--    这里存在一个问题 resultType + select * 的映射依赖全局配置 -->
<!--    因为 resultType 是自动映射。
        通常，数据库列名会采用下划线形式 比如 `create_time`，而JAVA是驼峰形式的，比如 `createTime`
        也就是说，数据库的列名和 JAVA 成员名是不一致的
        因此，如果没有开启下划线转驼峰模式，就很容易获取到的结果为 null
        当然也有例外情况，就是数据库列名和 JAVA 成员名相同时

        因此，通常需要在 SpringBoot 配置中开启下划线转驼峰，`mybatis.configuration.map-underscore-to-camel-case=true`
        或者，通过 resultMap 显式做了列到属性的映射
  -->
<!--    <select id="getExampleById" resultType="com.demo.xTimerSystem.model.Example">-->
<!--        select * from example where example_id = #{exampleId};-->
<!--    </select>-->

<!--    resultMap 对应的是上述 resultMap 的 id -->
<!--    <include refid="Vo_Column_List"/> 是复用的 <sql> 标签-->
        <select id="getExampleById" resultMap="exampleMap">
            select <include refid="Vo_Column_List"/>
            from example
            where example_id = #{exampleId};
        </select>
</mapper>

```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!-- DOCTYPE 声明 -->
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<mapper namespace="com.demo.xTimerSystem.mapper.ExampleMapper">
```

- `namespace` 必须是 mapper 接口的全限定名。

##### 结果映射规则 resultMap

将数据库中的 `column` 映射到 Java 中的 `property`。其中，主键列映射使用 `<id>`，普通列映射使用 `<result>`。

```xml
    <resultMap id="exampleMap" type="com.demo.xTimerSystem.model.Example">
<!--        主键列映射 -->
        <id column="example_id" property="exampleId"/>
<!--        result 普通列映射 -->
        <result column="create_time" property="createTime"/>
        <result column="update_time" property="updateTime"/>
        <result column="example_name" property="exampleName"/>
        <result column="status" property="status"/>
    </resultMap>
```

- `id`：`resultMap` 的 `id`。使用 `resultMap` 时，通过该 `id` 指定。
- `type`：结果集要映射到实体类的权限定名
- `column`：MySQL 的列名
- `exampleId`：Java 对象的属性名

##### 可复用的 `<sql>`

- `<sql>` 用于抽取可复用的 SQL 片段

```xml
    <sql id="Vo_Column_List">
        `example_id`,
        `create_time`,
        `update_time`,
        `example_name`,
        `status`
    </sql>
```

- 在 SQL 语句中通过 `<include refid="sqlId"/>` 引用，其中 `refid` 对应的是定义 `<sql>` 时的 `id`。

```xml
<select id="getExampleById" resultMap="exampleMap">
    select <include refid="Vo_Column_List"/>
    from example
    where example_id = #{exampleId};
</select>
```

##### 插入方法

```xml
    <insert id="save" useGeneratedKeys="true" keyProperty="example.exampleId">
        insert into example (`example_name`,`status`)
        values (#{example.exampleName},#{example.status});
    </insert>
```

- `id`：对应 Mapper 中的方法名
- `useGeneratedKeys="true"`：告诉 MyBatis 使用 JDBC 的 `getGeneratedKeys()` 获取数据库的自增主键
- `keyProperty="example.exampleId"`：把获取到的主键回填到 `example.exampleId`
- `#{example.exampleName}`,`#{example.status}` 从 `exmaple` 对象中读取 `exampleName` 和 `status`

##### 删除方法

```xml
<!--    -->
    <delete id="deleteById">
        delete from example where example_id = #{exampleId};
    </delete>
```

- `#{}` 包裹的变量，为 Mapper 方法中 @Param 注解传递的变量的引用，类似于前端的 `${}`

##### 更新方法

```xml
    <update id="update">
        update example
        <set>
<!--            <if test="example.exampleId != null">-->
<!--                `example_id` = #{example.exampleId},-->
<!--            </if>-->
            <if test="example.exampleName != null">
                `example_name` = #{example.exampleName},
            </if>
            <if test="example.status != null">
                `status` = #{example.status},
            </if>
        </set>
        where example_id = #{example.exampleId};
    </update>

</mapper>
```

> `<set>` 会自动做两件事：
> 1. 在内容前插入 SET 关键字；
> 2. 去掉动态拼接后末尾多余的逗号。
> 因此，每个每个 `<if>` 里末尾写逗号是正确且常见的写法，最终的 SQL 不会多个逗号

##### 查询方法

```xml
<!--    <select id="getExampleById" resultType="com.demo.xTimerSystem.model.Example">-->
<!--        select * from example where example_id = #{exampleId};-->
<!--    </select>-->

<!--    resultMap 对应的是上述 resultMap 的 id -->
<!--    <include refid="Vo_Column_List"/> 是复用的 <sql> 标签-->
        <select id="getExampleById" resultMap="exampleMap">
            select <include refid="Vo_Column_List"/>
            from example
            where example_id = #{exampleId};
        </select>
```

> [!note] `resultType` + `select *` 的映射依赖全局配置
> - `resultType` 走的是**自动映射**(隐式映射)。自动映射能否把数据库列正确塞进 Java 属性，取决于「列名能否匹配上属性名」。
> - 而 MySQL 中列名和 Java 变量的命名风格不同。通常 MySQL 采用下划线风格， Java 采用驼峰风格。
> - 下划线与驼峰不一致时，，这个匹配会失败，结果就是对应属性为 `null`。
> 因此，对应的解决方案有几种
> - 开启下划线转驼峰：在 SpringBoot 配置中开启下划线转驼峰，`mybatis.configuration.map-underscore-to-camel-case=true`
> - 相同命名： MySQL 中列名和 Java 成员名使用相同的名称
> - 显式映射：通过 resultMap 显式做了列到属性的映射
