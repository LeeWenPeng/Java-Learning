## 什么是幂等性？

在数学中，幂等函数满足：

$$
f(x) = f(f(x))
$$

即对同一个输入，一次执行和多次执行结果相同。例如，绝对值函数，

$$
abs(x) = abs({abs({x})})
$$

计算机领域，幂等性是指，**同一个操作请求执行一次或多次，对系统状态造成的影响与执行一次相同**。

> [!note] 注意
> 不只是返回值相同，更重要的是 " 副作用 " 相同。
> - 也就是说，**后续重复执行不应产生额外业务副作用，最终状态与执行一次一致**。
> - 例如同一笔转账请求因超时重试多次，最终只能扣一次款。

## 为什么要幂等性原则？

因为网络不可靠、调用方可能超时重试、消息可能重复投递、前置服务可能重放请求。客户端认为 " 失败 " 的请求，服务端可能已经成功处理，只是响应丢了。所以接口层需要幂等，底层操作也最好可重入。

## 实现方式

### 唯一 Key / 唯一约束

- 用业务唯一号、请求 ID、消息 ID 等做唯一索引。重复插入时数据库返回唯一键冲突，从而判断重复。
- 关键点：不要只 " 先查再插 "，并发下会有竞态；应依赖数据库唯一索引做原子兜底。

### 状态机 / 条件更新

通过状态来判断是否要进行记录的更新。如果状态已经更改（不满足更新条件），则无法更新，也就是，影响行数为 0。

### 依托额外记录

无法用业务唯一 ID 或状态判断时，单独建请求记录表，记录 request_id / 业务键 / 处理状态。需要唯一索引防并发重复。

## 本项目的幂等处理

1. 通过唯一 ID：定时器 ID + 执行时间戳全局唯一确定一个定时任务。
2. 通过额外记录：基于定时器 ID 和执行时间戳检索 MySQL 定时任务记录表，判断是否重复执行。
