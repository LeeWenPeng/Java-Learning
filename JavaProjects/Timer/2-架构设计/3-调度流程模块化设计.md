# 调度器模块

> 负责二维分片的全局统筹分配
> - 在分布式场景中，对所有的二维分片资源进行统筹，最终保证每一个分片会由一个单独的触发器角色负责，做到不遗漏、不重复。

前情提要，每一次定时任务都从属于一个基于 `时间范围` 和 `桶号` 组成的二维分片。也就是，每一个二维分片内，存储一个基于 `执行时间` 排序的有序定时任务集合。

## 1 核心调度流程

1. 主动轮询：基于 time ticker 每隔 1s 进行主动轮询，基于当前时刻推算对应的时间范围表达式（分钟级）；
2. 拼装分片：读取配置获取最大桶数，将其和时间范围拼接，获取目标分片们的 key；
3. 抢占锁：尝试抢占对于每一个二维分片的分布式锁 ，设置锁过期时间 `N` 满足 `1T < N < 2T`（即一倍到两倍分片时间之间）。
	- _当前预设锁时间为：`70s`_
4. 拉起触发器：抢锁成功，则调度启动一个触发器进行作业。

# 触发器模块

> 按时唤醒二维分片内的定时任务
> - 触发器模块承上启下。上承调度器模块（作为其子模块），下接执行器模块（作为其父模块）。

## 1 核心触发流程

1. 持续轮询：当触发器被调度器启动后，在对应分片的时间范围内，对分片进行间隔 `1s` 的持续轮询，并将达到执行条件的任务取出；
2. 协程分发：不断从协程池中取出对应任务数量的协程，在协程中启用执行器模块，用于执行任务；
3. 锁续期：触发器协程完成任务后，将该分片对应的分布式锁过期时间更新为 `N > 2T`（大于两倍分片时间）。
	- _当前预设续期时间为：`130s`_

# 执行器模块

> 真正执行定时任务
> - 执行器由触发器异步启动，一个执行器协程对应一个定时任务。

任务执行流程

1. 幂等去重：执行器对定时任务进行幂等去重；
2. 拉取信息：根据 Redis 中获取的定时器 id，查询到定时器完整信息；
3. 执行任务：执行业务逻辑；
4. 状态落盘：更新 MySQL 中定时任务执行记录的状态为 `已执行`。
